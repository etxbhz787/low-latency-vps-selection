## 低延迟的“低”，到底由什么决定？

按影响大小排：回程路由 > 机房与用户的距离 > 商家的负载控制。多数人买之前只看了第二个。

距离决定物理下限。跨太平洋访问，线路再好，往返延迟也普遍在百毫秒级，这是绕不过去的物理规律。但日常体感的差距主要来自回程路由——普通线路晚高峰拥堵、丢包，ping 值看着还行，实际用起来一卡一卡。CN2 GIA 和联通 9929 这类优化回程，存在的意义就是解决晚高峰丢包，有商家直接把它写进了核心卖点。

负载是第三个变量，也最容易被忽略。共享型实例在邻居高峰期会偷 CPU：上面提到的那份对比里，Linode 和 AWS 的共享型实例在高峰时段出现可见的 CPU steal，而用独占 CPU 的 DigitalOcean Premium 和 Hetzner CPX 几乎为零。对延迟敏感的应用，这个差异比宣传页上的任何数字都实在。

所以下单前的顺序应该是：先定线路（中国方向问回程，欧美方向问位置），再比配置和价格。

## 比延迟更容易踩的四个坑

买 VPS 让人花冤枉钱的，往往不是延迟本身，而是标称参数背后的条款。这几个点建议逐条核对：

**限速条款。** 大带宽宣传和持续限速规则经常同时存在。Rabisu 的规则写得算直白：标准使用（网页流量、更新、备份）可以跑满 1Gbps，但 6 小时窗口内平均带宽超过 100Mbps，端口会被临时限速，官方说法是保大多数用户的体验。7×24 挂流媒体这类用途，买之前把 Burst/Sustained 条款找出来读。

**SLA 的真实含义。** 正常运行时间保证本质是服务积分机制：达不到承诺时，赔的通常是账户额度而不是现金，而且不保证你的业务不中断。营销页上的数字和合同条款里的数字也可能对不上，下单前翻条款里的 SLA 章节。真需要 99.99% 以上的实际可用性，做跨机房冗余比纠结两家宣传数字差 0.01% 有用得多。

**流量超量计费。** AWS Lightsail 超出套餐后 $0.09/GB，流量大的月份账单可能直接翻倍。对比一下：Hetzner 含 20TB，DigitalOcean 和 Vultr 含 5–6TB。数据库长得快的还要看块存储单价，Hetzner 是 $0.052/GB，DigitalOcean 收 $0.10/GB。

**邮件端口。** 不少商家默认封锁 25 端口防滥发，Spaceship 就是默认封、要发信得走中继服务或申请解锁。有自建邮件需求的，下单前先确认政策，别等付完款才发现发不了信。
